# P17 — Do candle / technical-analysis / multi-dimensional trend features predict KX*15M outcomes? (offline study, 2026-10-27)

**Verdict (one paragraph).** No. Across 36 days x 3 assets (3,460 windows each; 1,542 strictly out-of-sample per asset), no candle, multi-timeframe, cross-asset, regime, volume or streak dimension adds measurable skill on top of the within-window partial move. At T-1m the full model (all 6 dimensions, logistic) changes AUC by **-0.18 to -0.23 bp** (i.e. -0.0018..-0.0023, every 95% day-bootstrap CI excludes zero on the negative side), and trading its disagreements with the partial-move baseline at a 5c-after-fee threshold returns **-0.9 to -0.0 c/contract** (BTC -0.47 +- 1.81, ETH -0.03 +- 2.19, SOL -0.94 +- 1.92). Gradient boosting is no better. At the window open, where a chart reader would act, candle-only models are AUC 0.50-0.55 and earn +0.1..+1.7 c/ct against a 50c market before spread (SE ~1.1c) — indistinguishable from zero and far below the 5c gate. Recommendation: **register P17 as scored-only, do not wire any TA feature into the P13/P16 decision**; keep `candles.py` as a logged context so the negative can be re-tested at n >= 6,000 windows without touching the runners.

## 1. Data and label

- Coinbase Exchange public REST, 1-min candles, 2026-09-22 00:00Z -> 2026-10-28 01:29Z, BTC/ETH/SOL-USD; 51,928-51,930 of 51,930 expected minutes (coverage 1.000). Cached at `data/candles/<A>_1m.parquet` (+ `.ranges.json` so refetches only hit missing blocks; ~170 requests/asset at ~3 req/s).
- Label: YES iff proxy(avg of index in minute before close) > proxy(avg in minute before open). Proxy = OHLC4 of the Coinbase 1-min candle that spans that minute.
- **Approximation error, measured** against the OFFICIAL settlement feed we now record (`data/cfb/<A>.jsonl`, 176 complete 60-s averages per asset on minute boundaries): OHLC4 vs official avg60: BTC bias -0.20 bp, sd **1.01 bp**; ETH -0.33 / 0.91 bp; SOL -1.89 / 0.80 bp (SOL's bias is the Coinbase-vs-index basis; it cancels in the direction label because both ends use the same proxy). Using the candle close instead doubles the error (sd 2.2-2.4 bp). The median |15-min move| is 7.6 / 9.8 / 13.7 bp, so ~5.3% of labels (per asset) flip between OHLC4 and close proxies; the error is symmetric and independent of the features, so it attenuates measured AUC slightly but cannot create or hide a real edge of economic size.
- YES rate 0.492 (BTC/ETH/SOL identical to 3 dp): direction is a coin flip, as expected.

## 2. Features (`src/predhft/candles.py: features_at`)

All computed from candles that **closed at or before T** (tested: perturbing anything at or after T-59 s leaves every feature unchanged). Six dimensions, 60 features: **ta** (ret 1/5/15/60, EMA9/21 slope+cross+gap, RSI14, VWAP dev session/rolling-60, RV15/60/ratio, range position, engulfing/inside/three-in-a-row, prior-window move, time-of-day, volume z); **mtf** (EMA-slope direction on 1m/5m/15m/1h, HH-HL structure on 5m/15m/1h, `align_score` -4..+4); **regime** (ADX14 on 5m, variance ratio VR(15), trending flag, ret15/partial/prev-window x trending); **volume** (volume vs 60-min mean, volume-confirmed moves); **xasset** for ETH/SOL (BTC ret 1/5/15, BTC align, BTC partial move, relative strength, ratio momentum, BTC lead); **streak** (last 3 Kalshi outcomes).

Baseline (`BASE`): `partial_move_bp` (last close vs open-average proxy) and `partial_z` (= partial / (rv60 * sqrt(minutes remaining))). Note T-1m here means the last **closed** candle at T-60 s; the live P13/P16 edge from the inside-the-final-minute partial average is *not* representable with 1-min candles and is not what is being tested.

## 3. Method

Walk-forward: days 1-20 train only; then 4-day test blocks, model refit on all prior days before each block (OOS = 16 days, 1,542 windows per asset per decision time). Models: logistic (median-impute, standardise, L2) and HistGradientBoosting (depth 3, 150 trees, min leaf 40). Nested comparison: base vs base+dim vs base+all vs candles-only; delta-AUC with 600-draw **day-block bootstrap** (paired). Economics: no historical Kalshi quotes exist for these series, so p_market := the baseline model's own OOS probability (and, separately, a 50c market for the open). Rule: buy the favoured side when model - market - fee(0.07 p(1-p)) >= 5c; pay the market price with zero spread (optimistic for the challenger).

**Specific hypotheses**

- *Multi-timeframe alignment*: `align_score` univariate AUC .49-.50 at open; .68-.78 at T-5m/T-1m but entirely because it embeds the partial move (adds -.000..-.002 on top).
- *Cross-asset lead-lag*: BTC's last 1-min move predicts ETH/SOL's next window with AUC .540 / .548 at open — but ETH/SOL's *own* last minute does the same (.543) and the baseline already has it (dAUC xasset -.005 / -.000). BTC ret5 - own ret5 ("catch-up") is .479/.472, i.e. the lagged leg has *already* moved. Relative strength and ratio momentum: .49-.50.
- *Regime interactions*: inside trending (ADX>=25) vs ranging windows at open, ret15 AUC .507/.484 (BTC), .503/.510 (ETH), .489/.505 (SOL); prev-window direction .48-.51 in both. Momentum does not switch on in trends at this horizon.
- *Volume confirmation*: `vol_conf_partial` is the strongest non-base feature (.992 at T-1m) and is just partial_move x volume; nested dAUC +.000/-.000.
- *Streak* (last 3 Kalshi outcomes): |AUC-.5| < .01 everywhere.
- *Candle patterns* (engulfing, inside, three-in-a-row): all within .49-.51 univariate.

## 5. Limits

Proxy label (1 bp sd, 5% flips); Coinbase spot not the CF index; no historical Kalshi quotes, so "edge" is vs our own baseline or vs 50c, not vs a real book; zero spread assumed; 16 OOS days (one regime, ~Oct 2026); decision times quantised to closed 1-min candles; six dimensions x three T x three assets = many comparisons (we report all, pick none). None of these limits biases *against* finding a signal of >= 5c — the proxy noise is far smaller than the 5c gate.

## 6. Proposed PREREG entry

**P17 — Chart-reader context (scored-only; registered 2026-10-27, after the offline study above, before any live scoring).**
- Hypothesis H0 (favoured by the offline data): candle/TA/MTF/cross-asset/regime/volume/streak features add zero AUC and zero cents of edge beyond the final-minute projection p_cal at T-55..T-10 s.
- H1 (to be falsified): `features_at(df, T-60, ref_df=BTC, prior_outcomes)` improves OOS Brier over p_cal by >= 0.005 **and** a 5c-after-fee disagreement rule earns >= +3 c/ct at 2 sd.
- Decision rule under P17: **none**. Runners log the feature dict next to each final-minute snapshot (`ctx.candles`); no trade, size or threshold depends on it.
- n_required: 2,000 scored final-minute snapshots per asset (>= 21 days) — powered to detect dBrier 0.005 at 80% with the observed Brier sd ~0.12 — and >= 150 disagreements per asset for the economic test.
- Stop rule: at n_required, if H1 fails on all three assets, P17 is closed and `candles.py` stays a logging utility; if it passes on one asset, a P18 paper variant may be registered for that asset only. Early stop (close P17) if at n = 1,000 the pooled dBrier is <= 0 at its upper 95% bound.
