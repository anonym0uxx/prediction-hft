# P18 — Thompson lever selection for the final-minute rule (written 2026-10-27 19:20 PT)

Code: `src/predhft/ts_levers.py` (arms, counterfactual replay, Normal-Normal posteriors, Thompson selection, state), hook in `src/predhft/s7_live.py` (`--ts-levers`, default OFF), tests `tests/test_ts_levers.py` (19). State `data/ts/levers_state.json`, per-window arm log `data/ts/arm_pnl.jsonl` (live replays only; bootstrap writes state only), results cache `data/ts/results.json`.

## 1. What this is (and is not)

The P13/P16 rule has four execution levers whose right values we have been hand-tuning from 20-ish trades. Instead of bandit feedback we have **full information**: every settled 15M window can be replayed from the recorded book snapshots (`books.jsonl`, ~1-1.5 s cadence inside the final minute) plus the official result, and the realised per-contract P&L of *every* arm computed. So **all arms update every window**; Thompson sampling only (a) picks which arm places the one live paper bet, by probability matching over the posterior, and (b) reports P(best). Because learning does not depend on which arm is live, the live choice costs nothing in information — its only job is to generate real fills that check the replay's fill model.

## 2. Arms — 36, full factorial over the four levers that interact mechanically

| lever | values | why it is in the grid |
|---|---|---|
| edge threshold E | 3 / 5 / 7 c (p_cal − fill − fee) | the live gate that has kept P16 quiet since 15:20 PT |
| decision timing W | early T-55..T-30 · mid T-40..T-10 · late T-25..T-10 | price-path effect (REBASE §2.4): the first qualifying snapshot sets the fill |
| favourite cap C | 0.95 / 0.97 | registered P13 cap vs the SHARPE_PLAN executability amendment |
| order style O | take (ask+1 tick, next snapshot must still satisfy the cap = the live re-check, pay the worse of the two asks) · join (rest at our side's best bid; filled **only** if a later snapshot shows our side's ask strictly below our bid; maker fee 0) | fill quality is the lever Alon asked about; join is modelled pessimistically (no queue credit at equal price) |

These four interact (cap × timing through the price path, order × timing through time-to-cross, edge × cap because a 0.97 fill cannot carry 3c of edge), so I did not use an additive model for them: 36 arms = 3·3·2·2. Replaying 43 arms over 216 windows takes < 1 s, so the cost of a full grid is zero; the cost is statistical, handled by the n_min rule below.

Pruned out, with the reason:

- **Size {risk.size, ×0.5} is not an arm.** Per-contract P&L is identical for both; a posterior on per-contract P&L cannot distinguish them, and a posterior on $-P&L would merely learn sign(mean). It is **derived** from the chosen arm's posterior: full `risk.size` only when P(μ > 0) ≥ 0.75 and n ≥ 30 closes, otherwise 0.5× (never above `risk.size`, never below `min_lot`). Kelly-consistent and keeps `risk.size` as the ceiling.
- **Hour filter {all, US-day 06-16 PT, high-vol hours} is not an arm either.** It conditions on exogenous clock time, not on the trade, so it needs no replay: it is a *mask* over the same observations and is reported as a stratified posterior (§4). High-vol hours were learned from the data once and frozen in the state (`hivol_hours_pt = [1, 4, 6, 7, 8, 9, 22]` PT: top tercile of the per-window final-minute spot range, median by PT hour, 0.85 days of data — provisional, refreeze only via `--refreeze` and a PREREG note). PREREG already forbids hour-of-day sizing before a bucket has ≥ 40 opportunities; promotion to the grid follows the P18 rule in §6.
- **Reference arm** `E5-full-C95-take` = the incumbent P13/P16 rule (T-55..T-10, 5c, cap .95, take) is replayed and reported but not sampled.
- **Candidate arms (6, replayed, reported, NOT sampled)**: `E{3,5,7}-{early,mid}-C95-take-F50` add a *market-agreement floor*: our side must be priced ≥ 0.50 (buy only the market favourite). Added **after** seeing the bootstrap (every take loss below was a market longshot), therefore in-sample for all closes before P18_T0 and excluded from selection until it has ≥ 30 post-registration closes.

Posterior: per arm, Normal-Normal with known-variance approximation on **cents per contract**, one observation per settlement close (the three 15M assets share `close_ts` with 0.7-0.9 correlated errors → the close is the cluster; its observation is the mean over the assets the arm traded). μ₀ = 0 (the market is calibrated — REBASE verdict), τ₀ = 10 c; σ² = pooled cluster variance shrunk to 35 c with 5 pseudo-clusters, floored at 15 c. P(best) by Monte Carlo over the 36 grid arms.

## 4. Reading the table honestly

1. **Nothing is distinguishable from zero and nothing has n ≥ 30.** The best grid arm has P(best) 0.044 against a uniform 0.028. No arm qualifies for the "recommended default with n ≥ 30" criterion; the incumbent reference rule is the *worst* arm in the table (−10.1 ± 12.9 c/ct, 8 trades), but with 7 clusters that is a 0.8σ statement.
2. **The timing lever is decided by supply, not by edge:** 7-12 trades for `early`, 1-3 for `mid`/`late`. By T-40 the favourite is ≥ 0.97 in essentially every window where the projection is informative. The single mid/late take trade (−65.7 c) is the ETH 18:15Z loss at 0.62 with T-17 s left. *Whatever else is true, decisions after T-40 are not where this rule's P&L lives.*
3. **The cap lever is degenerate under any edge threshold ≥ 3c** (identical n for C95/C97 in all take rows): a fill at 0.97 + 1 tick + 0.2 c fee cannot carry 3 c of edge with p ≤ 1. The .95-vs-.97 question only exists for the join arms (bid .96 with p_cal .99) and there it adds nothing (same n). The SHARPE_PLAN executability amendment and the REBASE cap debate were about a lever that the calibrated-edge gate already removed.
4. **The edge lever: 3c vs 5c vs 7c changes one trade** (E3 adds the ETH 14:30Z NO @0.67 loss). Where the computed edge is largest the trade is worst: of the 15 take entries the losses are 18:30Z BTC (NO @0.50, p_cal .78 vs market .50), 18:30Z ETH (NO @0.19-0.67, p_cal .76-.90 vs market .2-.4), 06:45Z ETH (YES @0.27, p_cal .65), 18:15Z ETH (@0.62) — **every take loss is a case where the market priced our side ≤ 0.5 and p_cal disagreed by 25-50 c; the 10 trades where our side was already the market favourite (0.64-0.96) went 10/10.** That is the P15/REBASE finding again ("when they disagree below 2 bp the market is right 23/25") showing up as a lever. It is why the F50 candidates sit on top — and why they are candidates, not arms: I saw it in this sample.
5. **Join is not a free lunch:** 10-12 fills at −3.5 to −7.2 c. Three of the joins filled *because* the price was collapsing through us (20:00Z SOL filled at T-18 s at 0.85, lost 85 c). Strict-crossing fills are adverse-selected, exactly as the maker-score family (P10 maker5) assumed.
6. **Hour overlay (masks, not arms; n in single digits everywhere):** US-day 06-16 PT: E3-early take +1.5 (n=3), join −23 (n=4); off-day: take −4.4 (n=4), join +7.6 (n=7); learned high-vol hours: take +16.9 (n=2), join +19.7 (n=3). Nothing here is evidence; it is the shape of the dashboard the parent will read in a week.

**Recommended default arm: none qualifies (no arm has n ≥ 30).** Until one does, the hook samples by probability matching with the prior dominating (every arm ≈ 2.4-4.4 %, join arms excluded from live selection), with the P18 guard below. If forced to name one on posterior mean among take arms it is `E7-early-C95-take` (−0.1 ± 12.4 c/ct, P(μ>0) 0.50) — i.e. the data says "7c threshold, decide before T-30, nothing else matters", and it says it at zero significance.

## 5. Live hook (`s7_live.run(..., ts_levers=True)`, CLI `--ts-levers`, requires `--proj-gate`)

- At the first poll of each close: `ts_levers.sample_best(live_only=True)` → one take arm; logged `TS ARM <id> close=… size_mult=… n=… post_mean=… P(best)=…`. The arm sets the fav cap, the timing window (skips logged as `ts_timing` in NOFILL reasons), the edge threshold in the P16 gate, and a size multiplier applied *after* `risk.size` (ceiling unchanged, `min_lot` floor). One bet per close, `risk.py` untouched.
- Every final-minute snapshot carries `ts_arm`; every trade row carries `ts_arm`, `ts_size_mult`, `ts_p_best`.
- When the window closes the snapshots go to a pending list; from `close_ts + 120 s` the runner fetches the result (one GET per window), replays **all 43 arms** (`replay_all`, basis_applied=True because the P13 runner records corrected spot), updates `data/ts/levers_state.json` under a cross-process file lock (three runners share it; idempotent per (arm, close, series)), appends one row per traded arm to `data/ts/arm_pnl.jsonl`, logs `TS REPLAY <ticker> result=… arms_traded=k/43 live_arm=<id>:<pnl> ref=<pnl>`.
- Off by default: with `ts_levers=False` the code path is the P13/P16 rule unchanged (cap .95, edge .05, full window, no multiplier). Join arms are never selected live (the paper runner cannot rest orders); they keep being scored by the replay.
- Backfill / restart safety: `uv run python -m predhft.ts_levers bootstrap` is idempotent and can be run any time to replay windows a restart lost.
